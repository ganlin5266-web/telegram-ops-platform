# Historical P4 mapping semantics for P5-B

009's import contract explicitly supplied businessDate, currency, timezone and a flat canonical-field-to-column mapping. It validated platform currency/timezone, normalized deposit with exact BigInt decimal arithmetic and stored NUMERIC(28,6). No scaling, rounding, exchange rate or inferred date is involved. Evidence retains raw cells and their digest; revisions retain normalized values and a completeness-aware digest. The database validates revision values and protects history. 010 leaves the zero mapping_digest on these historical batches; modern writes always calculate their mapping digest.

The shared resolver used by Draft, Preview and Evaluation checks batch scope/currency/timezone first. Modern metadata must have adapterId, mappingVersion, active status and an approved available deposit field. Invalid or partial modern metadata never falls back to legacy.

Legacy requires only recognized flat canonical keys, explicit unique UID/deposit column mappings, the preserved zero digest, CSV/XLSX source, an exact valid business date, reconstructed 009 metadata/scope hashes, complete evidence row count, raw-row hashes, canonical normalized shape, exact raw-to-normalized deposit equality, no fatal row issues, and revision scope/evidence/value/digest consistency. Empty/unknown evidence is rejected. NULL remains NULL; incomplete/unknown/conflicting completeness does not become eligibility. Current platform and rule currency/timezone must match the batch.

The compatibility result records `semanticsSource: legacy_explicit_canonical_v1` and the canonical mapping fingerprint. It does not invent adapterId/mappingVersion or update P4 history. Entitlement revisions retain this result in source_metric_semantics and reference the actual fact revision/batch/evidence. Existing schema suffices; migrations and runtime grants are unchanged. Runtime does not gain schema_migrations access. The zero marker alone is insufficient; historical provenance is additionally checked during acceptance (both approved Staging batches were created before 010). This is not cryptographic proof against a database owner deliberately forging an entire historical dataset.

Staging read-only evidence for both existing 2026-09-26 FUN66 batches confirmed all checks, BRL, America/Sao_Paulo, active/complete, 4 evidence rows and 3 revisions. Automated tests reproduce the 009 writer only in isolated test databases. No historical Staging data is rewritten. Publishing, evaluation enablement and rewards remain separately gated.
